# Сверка — предложения поставщиков

Инструмент импорта прайсов CSV/TSV/XLSX и сравнения стоимости закупки с упаковкой, минимальным заказом, шагом, налоговыми условиями, доставкой и сроком.

Статус: браузерное статическое демо. Публичный адрес после проверки публикации: https://skrlv.github.io/supplier-compare-demo/ . Отдельный локальный API реализован и проверяется самостоятельно; браузерный интерфейс его не вызывает.

## Что можно сделать

- Загрузить каталог и несколько прайсов; выбрать лист Excel, проверить первые строки и назначить столбцы.
- Нормализовать шт., массу, объём, длину и площадь; раскрыть явно заданную упаковку.
- Автоматически связать точный общий код каталога при `sku_scope=catalog`. Названия, синонимы и коды поставщика дают кандидатов для ручной проверки.
- Сохранить ручной выбор или исключение с обязательным основанием. При изменении исходных условий или каталога прежнее подтверждение теряет силу.
- Исправить условия отдельно от оригинальной строки и пересчитать предложения при изменении потребности.
- Сравнить отдельные заказы по платёжной сумме и сроку в каждой валюте. Скачать JSON для продолжения и CSV для анализа.

Все цены, товары, названия поставщиков, ставки и сроки учебного примера вымышлены. Данные обрабатываются в памяти вкладки, без загрузки на сервер и без сохранения после её закрытия. Скачайте JSON перед закрытием. Нет писем поставщикам, реальных заказов, курсов валют или внешних интеграций.

## Запуск и проверки

Нужен Node.js 22+ и npm. В папке проекта:

```sh
npm ci
npm test
npm run build
npm start
```

Локальный адрес: http://127.0.0.1:4199 . Не открывайте HTML через `file://`: модулям нужен HTTP. Сервер слушает только 127.0.0.1; `PORT=4200 npm start` меняет порт. После сборки `dist/` — самостоятельный статический сайт. ExcelJS уже включён в `web/vendor/`; интернет для обработки таблиц не требуется. `npm run examples` пересоздаёт синтетические таблицы.

## Воспроизводимый сценарий

1. Откройте учебный пример. Для потребности 250 шт. предложения A/B/C дают 2850 / 3420 / 5000 RUB, D — 29 USD отдельным рейтингом.
2. Измените потребность этого товара на 410 шт.: A закажет 5 упаковок по 100 шт., излишек 90 шт., итог 4550 RUB.
3. Откройте «На проверке», выберите товар для похожего названия и укажите основание. Подтвердите: строка появится в сравнении, если все условия полны и единицы совместимы.
4. Нажмите «Исправить условия»: оставьте доставку пустой. Строка не получит полного итога. Явный 0 означает бесплатную доставку.
5. Скачайте CSV и JSON. Восстановите JSON: оригиналы, правки, основания и новая потребность сохранятся, расчёт выполняется заново.
6. Для своего импорта сначала сохраните сессию, очистите пример, загрузите `examples/catalog.csv`, затем `examples/offers.xlsx`, выберите лист и проверьте назначения. Повторный импорт, конфликт ID, формула и повреждённый файл отклоняются до изменения текущей сессии.

## Границы расчёта

Цена относится к одной единице продажи `price_unit`. Для упаковки её содержимое = `pack_size × content_unit`. MOQ и шаг — в **той же единице продажи**, а не в базовых штуках или деньгах. Кратность считается от нуля:

`N = ceil(max(MOQ, Q / U) / step) × step`

`Поставка = N × U`; `Излишек = Поставка − Q`; `Платёж = N × цена с налогом + доставка`.

Шт. и упаковки неделимы. Граммы переводятся в кг, мл в л, см/мм в м. Разные размерности (кг/шт., кг/л., м/м²) не объединяются даже по ручному выбору. Потребность в интерфейсе вводится в исходной единице каталога: 12500 для каталога в граммах, а не 12,5.

`included` — налог уже включён; `excluded` требует явной ставки `vat_rate`, в том числе 0; `unknown` не даёт полного итога. Ставки задаёт пользователь; программа не определяет действующее налогообложение. Доставка — известная итоговая сумма с применимыми налогами в валюте предложения **для отдельного заказа одного товара**. Пустая доставка не равна нулю. Итоги разных товаров не складываются в корзину, доставка не распределяется между ними.

Срок — календарные дни от общего для сравниваемых предложений события (например, подтверждения заказа). Диапазон ранжируется по верхней границе. Даты, Excel serial, «в наличии» и рабочие дни не преобразуются догадкой. Перед сравнением пользователь должен согласовать событие отсчёта, место/условия поставки, одинаковую спецификацию и налоговые условия. Текстовые оговорки «от», пороги бесплатной доставки и скидки не поддерживаются: сначала требуется точное условие. Пошлины, вычеты и банковские комиссии не вычисляются.

Валюты сравниваются отдельно, FX отсутствует. Точные десятичные расчёты используют рациональные числа BigInt, итог округляется decimal half-up только в конце (обычно 2 знака; JPY/KRW — 0, KWD/BHD — 3). При равном платеже предпочтение у меньшего срока, затем стабильного ID. «Цена единицы без доставки», «платёж / потребность» и «платёж / поставка» показаны отдельно.

## Файлы и импорт

Схема и примеры: [FORMAT.md](FORMAT.md), `examples/`. Неоднозначное числовое форматирование трактуется по объявленному правилу: десятичный разделитель точка или запятая, пробел — разделитель разрядов; `1,234` означает 1.234. Ведущие нули артикулов сохраняйте текстовым форматом Excel. Числовая ячейка не доказывает потерянные ведущие нули.

Ограничения: 5 МБ таблица, 5000 строк каждого вида во всей сессии, 100 столбцов; сессия до 16 МБ исходных данных/истории, JSON до 128 МБ; XLS не поддерживается. Формулы в XLSX отклоняются даже с сохранённым результатом. CSV не исполняется. Экспорт защищает текстовые клетки от интерпретации как формулы. Оригинальная строка, файл/лист/номер, назначения столбцов, правки, решения, ошибки и расчёты доступны в выгрузках. JSON восстанавливается только как сессия версии 2; импортировать произвольный чужой JSON нельзя.

## Локальный API

Сервер без базы и авторизации для работы на своём компьютере. Не публикуйте его в интернет как готовый многопользовательский сервис. Данные запроса не сохраняются. Нет CORS wildcard, есть лимит тела 5 МБ и запрет обхода путей.

```sh
curl -X POST 'http://127.0.0.1:4199/api/import?kind=offers&name=offers.xlsx&sheet=0' --data-binary @examples/offers.xlsx
curl -X POST 'http://127.0.0.1:4199/api/analyze' -H 'Content-Type: application/json' --data '{"catalog":[],"offers":[]}'
```

`/api/import` возвращает преобразованные строки и список листов; автоматическое назначение для канонических/русских заголовков. Для нестандартной таблицы используйте интерактивное назначение в браузере или экспортируемые функции `readTable/autoMapping/mapRows`. `/api/analyze` принимает `{catalog,offers,decisions,quantities}`. Исправления сначала применяются к копии предложения. Договор API: `web/engine.js`, `web/lib/import.js`, `web/session.js`. Снимок расчёта из JSON не принимается за достоверный: результат пересчитывается.

## Структура и публикация

`web/` — интерфейс, расчёт и импорт; `examples/` — синтетические CSV/XLSX и отрицательные примеры; `test/` — автоматические проверки; `server.mjs` — локальный API; `scripts/` — сборка/генерация; `dist/` — результат сборки. Данные пользователей и секреты в репозитории отсутствуют.

Отдельный репозиторий: https://github.com/skrlv/supplier-compare-demo . Официальный workflow `.github/workflows/pages.yml` запускает проверки, собирает `dist`, публикует через `actions/configure-pages`, `actions/upload-pages-artifact`, `actions/deploy-pages`. В настройках Pages используется `build_type=workflow`. Относительные пути поддерживают `/supplier-compare-demo/`. GitHub Pages выполняет только браузерную часть и не запускает локальный API.

Источники библиотек, закреплённые версии и лицензии: [THIRD-PARTY.md](THIRD-PARTY.md). Иконка и стили взяты из предоставленной заготовки и доработаны в этом проекте; внешних фотографий, шрифтов и трекеров нет. Код проекта — MIT, см. LICENSE.
